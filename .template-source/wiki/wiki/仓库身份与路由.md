# 仓库身份与路由

根 `yss-project.yaml` 声明 `schema_version: 1` 与合法 `repository_mode`；当前模板源值为 `template-source`。缺失、非法或不支持的身份停止受影响路由并检查迁移，不从目录、远程或占位符推断。

路径相对当前治理仓根；进入独立实现仓后消费本地入口解释身份、工具和流程，共同授权、用户工作保护与允许写范围继续有效。只读问答和定位读取 Context 与相关来源，不创建 Ticket/checkpoint，不改批准或状态，也不启动回归。

新实例使用 `yss init --profile backend --root <新目录>`，元数据为 `.yss.json`；历史 CLI/metadata 仅作旧身份识别，旧实例须显式迁移，未完事务用匹配固定旧执行器恢复。

项目实例先消费本地 `harness-orchestrator` 的 `request_triage.delivery_path`，用具备该能力的 `yss lifecycle route` 核验任务、实现仓与完整基线 SHA。daily 维护同一 Ticket/PR，绑定范围、验收、工程/基线、Skills、实际测试、独立审查与回滚，不要求阶段 checkpoint、正式 Slice 合同或多级批准；`yss lifecycle verify-daily` 失败、缺独立审查或阻断未关闭时不能完成。 本仓只承担后端交付；另一端角色仅提供只读输入评审，不获得另一端代码写范围。本端完成不代表跨端业务验收，统一管理方核验整体证据。

历史 `create-yss-spec` 接管契约注明本 Harness 不使用、不履行，不能用它替代当前 Profile 的初始化和路由。参见 [[模板总览]]、[[产品研发生命周期]]。
