# 切片实现合同

Slice Implementation Contract 是 `stage.slice-contract` 进入实现前的统一实现合同：由 `yss-implementation-contract-compiler` 根据冻结资产和 [[垂直切片Ticket]] 编译草案，再由 Harness Orchestrator 批准并持久化。正式垂直切片必须消费已批准、已持久化且版本当前的合同。实现合同编译器 只生成草案，不得输出 `approved`、`ready-for-agent` 或 `completed`。

实现合同编译器 先读 [[Spec基线]]、战术设计或 `not-applicable`、[[OpenAPI契约]] Freeze 或无 API 影响、数据 / UI 输入、实现仓库和验证命令。输入缺失、未批准或 `stale` 时输出 `blocked`，交回 `harness-orchestrator`（见 [[产品研发生命周期]]）。编译结果只能是草案状态，见 [[YSS路由与合同编译]] 与 [[Ticket与流程状态]]。

合同固定包含 `architecture`、`frontend`、`backend`、`testing` 四个分区，四个 Agent 必须消费同一 `contract_id` / `contract_version`。路径越界、证据缺失、未执行验证、`drift`、`violation` 或 `new_impacts` 时停止实现并重新路由。`seam-deferred` 只能显式记录风险、责任人、后续 Ticket、验证计划和目标版本或发布日期。

脚手架只在 `scaffold_status=required` 且受控生成合同已批准并持久化后运行，只产生机械骨架；业务行为回到 实现合同编译器 并使用 `behavior-tdd`。
