# 切片实现合同

本仓只承担后端交付；另一端角色仅提供只读输入评审，不获得另一端代码写范围。本端完成不代表跨端业务验收，统一管理方核验整体证据。

governed 可以从原始业务需求完成本地适用 Plan/Spec，也可以复用当前批准的本地或上游输入；冲突回交权威方，不静默改写。正式实现仍须已批准、持久化且当前的 Slice Implementation Contract、必要门禁与允许写范围。

正式 Slice Implementation Contract 必须被持久化且批准版本当前，专项技能消费合同并返回实际执行证据；编译器只出草案，不批准、不设置 ready-for-agent、不宣布完成。统一合同固定包含 architecture/frontend/backend/testing 四分区及 Common、Contract、Cross-repo 信息，四个 Agent 消费同一 contract_id/contract_version。

脚手架必须满足 scaffold_status、当前确认的架构决定、已批准且持久化的 schema v4 生成合同；只生成机械骨架，既有工程不覆盖，业务行为回合同编译与 behavior-tdd。

越界、必要证据缺失或验证未执行时停止受影响实现；drift/new_impacts 先调查更新范围并使受影响合同失效，不先完成代码再补合同。参见 [[YSS路由与合同编译]]。
