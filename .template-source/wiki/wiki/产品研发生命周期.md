# 产品研发生命周期

`project-instance` 按产品研发生命周期分诊任务。主阶段以 `docs/process/lifecycle-registry.yaml` 为准，当前五阶段为：`stage.harness-entry`、`stage.tactical-design`、`stage.slice-contract`、`stage.slice-implementation`、`stage.verification`。编排入口是 `harness-orchestrator`，不是已退役的 `yss-product-lifecycle`。

任务开始时先读当前仓库根 `yss-project.yaml` 确认仓库身份（见 [[仓库身份与路由]]），再用 [[影响面分诊与流程裁剪]] 判定变更类型、影响面和最近可信阶段，然后按注册表执行命中的工作单元与 [[条件强制门禁]]。条件门禁全部按影响面强制：命中必须完成；未命中只记录 `not-applicable` 及原因，不生成空文档。产物、工作单元和证据不得统称为门禁。

新功能或较大变更统一进入 `harness-orchestrator` 的 Harness Entry。存在领域行为、聚合、不变量、状态、一致性、Domain Event、Gateway 或持久化映射影响时，由 `role.architecture-agent` 使用 `yss-tactical-design` 形成 DDD Tactical Design Contract，并由测试 Agent 评审；无领域影响只记录 `not-applicable`。旧 Discovery / 战略设计入口 `yss-stage-decision` 已退役，迁移路径见 `docs/agents/skill-migrations.md`。`grill-with-docs`、`to-spec`、`to-tickets` 只是用户显式兼容入口。[[SpecDelta]] 只记录相对既有冻结 Spec 基线的高风险行为差异。

API 契约变更先形成 OpenAPI 3.1 Draft，经必要审查后 Freeze（见 [[OpenAPI契约]]），再进入实现。OpenAPI Freeze 或无 API 影响记录完成后，由 Harness Orchestrator 正式化为可独立验证的窄 [[垂直切片Ticket]]；禁止只按 Adapter / Application / Domain / Infrastructure 横向拆分。每个功能先建功能父 Ticket。正式实现必须消费已批准、已持久化且版本当前的 [[切片实现合同]]；`yss-implementation-contract-compiler` 只生成草案，不批准合同、不设置 `ready-for-agent`。

安全 / 权限不设独立生命周期资料或专属门禁。`seam-deferred` 只能显式记录风险、责任人、后续 Ticket、验证计划和目标版本或发布日期。
