# 模板总览

本仓是后端专职 Harness 的模板源。身份由根 `yss-project.yaml` 声明，入口与允许职责由当前 `AGENTS.md` 和 Harness Profile 解释；README 与 Wiki 不另定义权限。

`template-source` 只维护可复用治理资产，不生成产品阶段资产；生成的 `project-instance` 使用 `harness.backend-delivery`。本仓只承担后端交付；另一端角色仅提供只读输入评审，不获得另一端代码写范围。本端完成不代表跨端业务验收，统一管理方核验整体证据。

项目实例路由：项目实例先消费本地 `harness-orchestrator` 的 `request_triage.delivery_path`，用具备该能力的 `yss lifecycle route` 核验任务、实现仓与完整基线 SHA。daily 维护同一 Ticket/PR，绑定范围、验收、工程/基线、Skills、实际测试、独立审查与回滚，不要求阶段 checkpoint、正式 Slice 合同或多级批准；`yss lifecycle verify-daily` 失败、缺独立审查或阻断未关闭时不能完成。 governed 可以从原始业务需求完成本地适用 Plan/Spec，也可以复用当前批准的本地或上游输入；冲突回交权威方，不静默改写。正式实现仍须已批准、持久化且当前的 Slice Implementation Contract、必要门禁与允许写范围。

稳定业务语言消费唯一根 `CONTEXT.md`；技能身份、别名与发现面消费 active Registry，来源、哈希与投影完整性消费 `skills-lock.json`。参见 [[Agent入口规则]]、[[模板维护流程]] 与 [[技能投影与锁定]]。
