# 复盘与权威资产修订

发布后或阶段性完成后做复盘判断。复盘不是独立主阶段，也不再使用已删除的 `artifact.retrospective` 或 `stage.verification-release-retrospective`。`project-instance` 在 `stage.verification` 关闭 `gate.fresh-verification-passed` 与 `gate.merge-approved` 之后判断是否需要复盘；`template-source` 对应 `work-unit.release-and-rollback` 与权威资产回流。出现架构返工、验证返工、IMPORTANT / CRITICAL review finding 或人工确认延期时，落简体中文复盘并修订权威资产。编排入口是 `harness-orchestrator`（见 [[产品研发生命周期]]），不是已退役的 `yss-product-lifecycle`。

复盘输入包括验证证据、审查报告、Ticket 证据与 Git checkpoint（见 [[Fresh验证与独立审查]]、[[Ticket与流程状态]]）。落地文档可用 `docs/templates/retro-report-template.md`，包含「做得好的地方」「需要改进的地方」「改进动作」「沉淀去向」。发现回流到对应单一事实来源：领域词汇修订 `CONTEXT.md`（含英文标识词干），入口与硬门禁修订 `AGENTS.md`，主阶段 / 门禁 / 工作单元修订 `docs/process/lifecycle-registry.yaml`，影响面与 `not-applicable` 修订 `docs/process/harness-process-tailoring.md`，维护强度修订 `docs/process/maintenance-intensity.yaml`，技能问题进入 `maintaining-skills` 并更新 `skills-lock.json` 与 `docs/agents/yss-skill-registry.yaml`（见 [[模板维护流程]] 与 [[条件强制门禁]]）。

复盘修订仍按影响面分诊：命中触发条件才生成对应资产，未命中只记录 `not-applicable` 及原因，不生成空文档（见 [[影响面分诊与流程裁剪]]）。跨仓库契约偏差须同步到外部仓库责任边界，任一参与仓库未完成契约对齐和集成验证时，不得单独声称整体可发布（见 [[实现仓库与跨仓库契约]]）。

Git checkpoint 只包含本轮明确范围；获得用户授权后才提交或推送（见 [[Agent入口规则]]）。复盘记录是下一次入口分诊与影响面分析的输入，不替代权威源本身。
