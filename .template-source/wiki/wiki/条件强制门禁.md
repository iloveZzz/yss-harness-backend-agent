# 条件强制门禁

生命周期门禁只有影响面命中触发条件时才必须裁决；未触发时记录 `not-applicable` 及原因，不生成空文档。门禁不是产物、工作单元或证据的统称。

注册表当前门禁按 `id` 为：`gate.repository-identity-valid`、`gate.tactical-design-approved`、`gate.high-risk-architecture-confirmed`、`gate.slice-contract-approved`、`gate.slice-ready-for-agent`、`gate.openapi-freeze-confirmed`、`gate.fresh-verification-passed`、`gate.merge-approved`。它们分布在 [[产品研发生命周期]] 的五阶段：`harness-entry`、`tactical-design`、`slice-contract`、`slice-implementation`、`verification`。

[[影响面分诊与流程裁剪]] 只减少未触发的门禁，不得跳过已经命中的条件强制门禁。会签按 `docs/agents/digital-human-roles.yaml` 的 `gate_policy`：`gate.tactical-design-approved` 由架构 Agent 起草、测试 Agent 会签；高风险架构、OpenAPI Freeze 和 `gate.merge-approved` 保留生物人。

只有通过必要门禁、阻塞边已清除并具备直接实现条件的 [[垂直切片Ticket]] 才能使用 `ready-for-agent`。Spec 初稿、产品设计、原型、[[OpenAPI契约]] Draft 和待冻结资产使用 `ready-for-human`。进入实现前还须由 Harness Orchestrator 批准 [[切片实现合同]]；实现者不能承担命中的独立审查，完成结论必须基于 [[Fresh验证与独立审查]]。
