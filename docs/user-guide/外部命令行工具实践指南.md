# 后端专职 CLI 使用与升级指南

专职 CLI 为 `create-yss-harness-backend`，首版候选 `0.1.0`。npm 可安装状态以 registry 为准；发布前从同名 CLI 仓库执行 `npm pack`，安装实际 tgz 验收。

```sh
npx create-yss-harness-backend@latest init --target-dir /absolute/path/to/new-project --project-name 设备借用
npx create-yss-harness-backend@latest attach --target-dir /absolute/path/to/existing-project
npx create-yss-harness-backend@latest attach --target-dir /absolute/path/to/existing-project --apply
npx create-yss-harness-backend@latest sync --target-dir /absolute/path/to/new-project
npx create-yss-harness-backend@latest sync --target-dir /absolute/path/to/new-project --apply
```

init 只创建不存在或空目录；`--dry-run` 零写入。attach 支持已有业务代码仓和独立管理仓，仅接入清单中的治理资产。attach / sync 默认只预览，写入必须带 `--apply`。冲突整次暂停；确认备份覆盖后使用 `--apply --force`。业务源码、构建文件、Git、子模块和越界路径不能强制接管。

## 身份与版本

核对 `yss-project.yaml` 为 `project-instance`、`.yss-harness-backend.json` 为 `metadataSchemaVersion: 2`，其 `profileId` 为 `harness.backend-delivery`。来源模板完整提交、核心版本及摘要、分发清单和受管基线均记录在 metadata；不要手改这些记录。

旧仓内脚本生成的实例一律不兼容，不转换 metadata 或重建基线。其他家族、多个身份、未知 schema、缺失基线和损坏身份同样拒绝。不得通过删除身份文件伪装普通工程接入。新实例用同家族 CLI sync，不重复 attach。

## 同步与恢复

CLI 携带固定模板快照，init / attach / sync 离线执行。sync 保留只有本地发生的修改，模板与本地同时修改则报告冲突；上游删除也进入明确计划。

应用事务失败自动恢复内容、mode 与 metadata；成功后保留 `.yss-harness-state/backend/transactions/<id>/` 的备份和恢复清单。中断事务在预览时只诊断，下次 `--apply` 先恢复，再重新执行计划。后续并发修改或备份损坏会保留现场并报告未恢复路径。首版没有独立 rollback 命令。

`create-yss-harness-backend update` / `upgrade` 仅更新 CLI 程序，不同步项目；npx 和源码运行方式输出安装指引。`--json` 输出版本 1 的计划与结果协议。

旧 `scripts/instantiate-harness` 仅在新 npm 包可安装且通过 smoke test 后切换为退役提示；新包快照已经排除该工具，避免实例继续创建嵌套实例。
